1

安装扩展

打开 VS Code，按以下步骤安装：

  1. 点击左侧活动栏的 扩展图标（四个方块组成的图标，或按 Ctrl+Shift+X）
  2. 在搜索框输入：Foundry Toolkit
  3. 找到由 Microsoft 发布的 Foundry Toolkit for VS Code
  4. 点击 安装 按钮
🔍

预期界面：扩展市场中显示 "Foundry Toolkit for VS Code"
发布者为 Microsoft，带有蓝色验证徽章

如果之前安装过旧版的 AI Toolkit 或 Microsoft Foundry 扩展，建议先卸载旧版再安装新版，避免功能冲突。
2

首次启动与账号登录

安装完成后，左侧活动栏会出现 Foundry Toolkit 的图标（通常是一个 AI/机器人的图标）。点击它打开侧边栏。

你需要登录以下账号之一（根据使用场景）：
  • GitHub 账号 → 使用 GitHub Models（免费额度，适合初学者）
  • Azure 账号 → 使用 Microsoft Foundry 云端资源（适合生产部署）

登录步骤：

  1. 点击侧边栏顶部的 "Sign in" 或 "登录" 按钮
  2. 在弹出的浏览器窗口中选择登录方式
  3. 授权 VS Code 访问你的账号信息
  4. 返回 VS Code，看到账号头像/名称即表示登录成功
👤

预期界面：侧边栏顶部显示已登录的 GitHub/Azure 账号信息
下方展开模型目录、Agent Builder 等功能入口

3

在 Playground 中测试模型（最快上手方式）

不需要任何配置，先找个模型聊聊天试试：

1 点击侧边栏的 Model Catalog（模型目录）
↓
2 选择 GitHub 作为 Provider（无需 API Key，用 GitHub 账号即可）
↓
3 浏览模型列表，点击任意模型（如 GPT-4o）进入详情
↓
4 点击 "Open in Playground" 或 "在 Playground 中打开"
💬

预期界面：右侧或新标签页打开 Playground 界面
底部有输入框，上方是聊天历史，可切换不同模型参数

在 Playground 里你可以：

  • 直接输入问题，测试模型的回复质量
  • 点击齿轮图标 ⚙️ 调整 Temperature（创造性）、Max Tokens（最大长度）等参数
  • 上传图片测试多模态能力（如 GPT-4o Vision）
  • 点击 📎 附件按钮发送文件让模型分析
GitHub Models 有免费额度限制，适合学习和原型开发。如果需要更大规模使用，建议后续配置 Azure OpenAI 或其他付费 API。
4

使用 Agent Builder 构建你的第一个 AI 智能体

Agent Builder 是 Foundry Toolkit 的核心功能，让你像搭积木一样构建 AI Agent：

进入 Agent Builder：

  1. 在侧边栏找到 Agent Builder 或 Agents 入口
  2. 点击 "Create Agent" / "新建 Agent"
  3. 选择 Prompt Agent（提示词型，适合初学者）或 Hosted Agent（代码型，适合开发者）
🤖

预期界面：Agent Builder 编辑器界面
左侧是配置面板，右侧是测试聊天窗口

配置你的 Agent（以 Prompt Agent 为例）：

1 命名：给 Agent 起个名字，如 "代码审查助手"
2 编写 System Prompt：定义 Agent 的角色和行为
例如："你是一位资深的 Python 代码审查专家，专注于发现潜在的性能问题和安全漏洞。"
3 选择模型：从下拉菜单选择底层 LLM（如 GPT-4o、Claude 3.5 等）
4 添加工具（可选）：点击 "Add Tool" 集成 MCP 工具，如文件读取、网络搜索、代码执行等
5 定义输出格式（可选）：设置 Agent 必须按 JSON、Markdown 等结构化格式输出

实时测试：

配置完成后，右侧的测试窗口会实时可用。输入测试消息，观察 Agent 的回复是否符合预期。如果不满意，随时调整左侧的 Prompt 或参数。

写好 System Prompt 的秘诀：明确角色 + 具体任务 + 输出格式要求 + 边界限制。越具体，Agent 表现越好。
5

集成 MCP 工具（让 Agent 拥有"手脚"）

MCP（Model Context Protocol）是 Foundry Toolkit 的重要特性，让 Agent 能够调用外部工具执行实际操作。

添加工具的步骤：

  1. 在 Agent Builder 中，找到 Tools / 工具 区域
  2. 点击 "Add Tool" / "添加工具"
  3. 选择工具来源：
    • Built-in Tools：内置工具，如文件系统访问、终端执行
    • MCP Servers：本地或远程 MCP 服务（需提前配置）
    • Microsoft Foundry Tools：Azure 云端提供的工具
  4. 配置工具参数（如文件路径、API 端点等）
  5. 保存后，在测试窗口验证工具调用是否正常
🔧

预期界面：工具列表显示已添加的工具卡片
每张卡片显示工具名称、描述和配置状态

常用 MCP 工具示例：

  • filesystem — 读写本地文件
  • fetch — 发起 HTTP 请求获取网页内容
  • sqlite — 查询本地 SQLite 数据库
  • brave-search — 网络搜索（需配置 API Key）
# 示例：在 Agent 的 System Prompt 中引导工具使用 """ 你是一位数据分析助手。当用户询问天气时， 请使用 fetch 工具调用天气 API 获取实时数据。 当用户要求保存结果时，使用 filesystem 工具写入文件。 """
6

本地运行与调试（Inspector）

Foundry Toolkit 内置了 Agent Inspector，可以可视化查看 Agent 的思考过程和工具调用链。

使用 Inspector：

  1. 在 Agent Builder 的测试窗口发送一条消息
  2. 观察 Agent 的回复，如果它调用了工具，会看到工具调用的详细过程
  3. 点击侧边栏的 Inspector 标签，查看完整的执行轨迹：
    • 🧠 Thought：Agent 的思考步骤
    • 🔧 Tool Call：调用了什么工具，传入什么参数
    • 📥 Tool Result：工具返回的结果
    • 💬 Final Response：最终的回复内容
🔍

预期界面：Inspector 面板显示时间轴式的执行记录
每个步骤可展开查看详细输入输出

如果 Agent 没有按预期调用工具，检查 System Prompt 是否明确指示了使用工具的场景和方式。必要时在 Prompt 中给出具体的调用示例。
7

部署到云端（Microsoft Foundry Agent Service）

当你的 Agent 在本地测试通过后，可以一键部署到 Azure 云端，获得生产级的托管服务。

部署前提：

  • 已登录 Azure 账号
  • 在 Azure 上创建了 Microsoft Foundry 项目
  • 已配置 Azure 订阅和资源组

部署步骤：

  1. 在 Agent Builder 中，点击顶部的 "Deploy" / "部署" 按钮
  2. 选择部署目标：Microsoft Foundry Agent Service
  3. 选择或创建 Azure Container Registry（用于存放 Agent 镜像）
  4. 配置资源参数：CPU、内存、实例数量等
  5. 点击 "Deploy"，等待构建和部署完成
☁️

预期界面：部署进度面板显示构建、推送、部署各阶段状态
完成后提供访问端点和测试链接

部署后管理：

  • 在 VS Code 的 Foundry 资源面板中查看已部署的 Agent 列表
  • 点击 Agent 进入 Hosted Agent Playground，在云端环境测试
  • 查看实时日志和 OpenTelemetry 追踪数据
  • 进行版本管理：更新 Agent 后重新部署，保留历史版本
部署到 Azure 会产生费用。建议在开发和测试阶段使用本地模式或 GitHub Models 免费额度，确认功能完善后再进行云端部署。
8

本地模型支持（Ollama / ONNX）

如果你希望在完全离线的环境下使用，Foundry Toolkit 支持连接本地模型：

使用 Ollama（推荐）：

  1. 先安装 Ollama 并下载模型（如 ollama pull llama3）
  2. 确保 Ollama 服务正在运行（默认端口 11434）
  3. 在 Foundry Toolkit 的 Model Catalog 中，选择 Ollama Provider
  4. 应该能看到本地已下载的模型列表，点击即可在 Playground 中使用
# 在终端中启动 Ollama（保持运行） ollama serve # 拉取模型（以 Llama 3 为例） ollama pull llama3 # 验证模型列表 ollama list

使用 ONNX / Foundry Local：

  1. 在 VS Code 中安装 Foundry Local 相关组件
  2. 通过 Foundry Toolkit 的模型转换功能，将 Hugging Face 模型转为 ONNX 格式
  3. 配置本地推理加速（CPU / GPU / NPU）
本地模型的优势是数据完全不出境、无 API 费用、响应快。缺点是通常能力弱于 GPT-4o 等顶级云端模型，适合对隐私敏感或网络受限的场景。

常见问题排查

问题 解决方案
侧边栏没有 Foundry 图标 检查扩展是否已启用，尝试重新加载窗口（Ctrl+Shift+P → "Reload Window"）
登录 GitHub 后无法使用模型 检查 GitHub Models 的免费额度是否用完；或尝试切换其他 Provider
Agent 不调用工具 在 System Prompt 中明确说明"当...时请使用...工具"，并给出调用示例
Ollama 模型不显示 确认 Ollama 服务已启动（ollama serve），且 VS Code 能访问 localhost:11434
部署时提示权限错误 需要 Azure 的 User Access Administrator 或让管理员预分配 ACR 角色（见步骤 7 说明）

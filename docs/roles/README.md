# 角色工作流说明

本目录存放项目开发中各角色的信息提示词（Persona Prompt）。当一项功能涉及多个层面的改动时，按以下流程执行：

## 工作流程

```
需求输入
   │
   ▼
┌─────────────┐   1. 分析现状，输出设计文档（docs/*-design.md）
│  系统架构师  │      含：方案选型、影响面分析、任务拆分清单
└──────┬──────┘
       ▼
┌─────────────┐   2. 按设计文档的任务清单逐项实现
│ 数据库工程师 │      遵循 AGENTS.md 的安全约定（参数化/脱敏/中文注释）
└──────┬──────┘
       ▼
┌─────────────┐   3. 按设计文档的验收清单逐项验证
│  测试工程师  │      输出验证结论：通过 / 不通过 + 原因
└─────────────┘
```

## 强制规则

1. **先设计，后执行**：架构师的设计文档未产出前，不得修改任何代码。
2. **任务细化**：设计文档必须包含可逐项勾选的任务清单，每项任务可独立验证。
3. **遵守 AGENTS.md**：所有角色都必须遵守根目录 `AGENTS.md` 中的安全与编码约定。
4. **回写文档**：实现完成后，若配置结构、API、目录结构发生变化，同步更新 `README.md` 与 `AGENTS.md`。

## 角色清单

| 角色 | 文件 | 职责 |
|------|------|------|
| 系统架构师 | [architect.md](architect.md) | 现状分析、方案设计、任务拆分 |
| 数据库工程师 | [db-engineer.md](db-engineer.md) | 按设计实现数据库相关改动 |
| 测试工程师 | [qa-engineer.md](qa-engineer.md) | 构建验证、回归检查、验收 |
